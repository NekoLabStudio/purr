# Purr 0.2.0


## What's new

- `InputBindings`: players change their controls and keep them, saved in the user folder over your Input Map's defaults. Controllers are found by name rather than number, axes can be calibrated, sets of bindings switch on with contexts, and each local player can have their own controllers and bindings. See [Controls](/modules/controls/).
- Button prompts for whatever controller the player is holding (Xbox, PlayStation, Nintendo, Steam Deck, keyboard and mouse, and Logitech's G29, G920 and G923 wheels), as an `InputPrompt` node, an image or inline in text. Purr ships Kenney's Input Prompts in a vector style and a pixel art one, and games can use their own images.
- `FrameBudget`: time your game's heavy work by name, and a long frame prints what took its time. Work that can wait runs a slice at a time within a budget each frame. See [Graphics settings](/modules/graphics/#long-frames).
- `WorldOrigin`: a floating origin for large worlds. The world shifts back under the player in whole steps, with map positions to save and send, and a `map_offset` shader global. See [Large worlds](/modules/world/).
- `RenderingServer.scenario_shift()` and `PhysicsServer3D.space_shift()` move everything in a scenario or physics space at once, which `WorldOrigin` uses: a shift of a large world costs a fraction of moving it node by node. `space_shift()` works with Jolt; with Godot Physics it returns `false` and objects move one by one.
- `WorldStreamer`: loads a large world's cells round the player in the background, joining them a few nodes a frame, with lighter far scenes beyond. See [Large worlds](/modules/world/#streaming).
- `MultiMeshBody3D`: collision for each instance of a `MultiMesh`, made a few dozen shapes a frame. See [Large worlds](/modules/world/#props-with-collision).
- `LightPool3D`: a few real lights kept on the best of thousands of light points round the player, fading as they move. See [Large worlds](/modules/world/#lights-at-night).
- `ReflectionProbePool`: reflection probes at the nearest of many sites round the player, placed and captured one a frame. See [Large worlds](/modules/world/#reflections).
- `DebugDraw`: draw lines, arrows, boxes, spheres, paths and text from anywhere, in 3D and 2D, for a frame or a few seconds, and list values in a corner of the screen. On in debug builds. See [Debug tools](/modules/debug-tools/).
- `DebugDraw.performance_overlay` (or `perf` in the console): frame times, CPU and GPU time with the costliest render passes, and draw calls and memory, in the corner of the screen. See [Debug tools](/modules/debug-tools/#performance-overlay).
- `Console`: an in-game console that opens with the key under Escape, shows what the game prints and runs commands you add, with arguments converted to the types your method declares. On in debug builds. See [Debug tools](/modules/debug-tools/#console).
- `profile` in the console records some seconds of play and saves a report: frame times, the longest frames and the script functions that took longest. It works without the editor, and debug builds now name script functions for it. See [Debug tools](/modules/debug-tools/#profiling).
- On a Mac, the editor and debug exports mark the engine's work for Instruments, so a recording shows each frame and the engine's steps. See [Debug tools](/modules/debug-tools/#profiling).
- `purr --run-tests` runs your game's tests: scripts in `tests/` that extend `TestCase`, with assertions that say where they failed, awaits (a test still running after `testing/timeout_seconds`, 30 by default, fails), and a JUnit report for CI. See [Testing](/modules/testing/).
- `purr --check-project` reports scripts that don't compile, scenes and resources that need missing files, and nodes' configuration warnings. See [Testing](/modules/testing/#checking-the-project).
- `VirtualCamera3D` and `VirtualCamera2D`: cameras that follow, orbit, ride a rail or frame a group, with the scene's camera taking the place of the one with the highest priority and blending between them, and a shake. See [Cameras](/modules/cameras/).
- Behaviour trees: `BehaviorTreePlayer` runs a `BehaviorTree` for a character, with built-in sequences, selectors, parallels, repeats, cooldowns, time limits and waits, and tasks you write by extending `BehaviorTask`, edited in a Behavior Tree dock that also shows what each task is doing while the game runs. `BehaviorStateMachine` and `BehaviorState` are state machines, with events, guards and machines inside machines. See [Behaviour trees and state machines](/modules/behavior-trees/).
- `Terrain3D`: a landscape you sculpt, texture and cut holes in from the 3D view's toolbar, or import from a heightmap, textured with images as texture packs ship them, with ground marked for navigation baking, with grass and rocks scattered over it, collision and an ocean, and it stays put on the map when `WorldOrigin` shifts the world and streams its regions round the camera when it's too big to keep in memory. It's based on the Terrain3D plugin and keeps its names and files, so projects made with the plugin keep their terrain: remove the plugin's folder. See [Terrain](/modules/terrain/).
- `Scatter3D`: copies of a mesh scattered over the floors, rocks and terrain below a box, by density, slope, scale and turn, drawn as one MultiMesh and optionally solid. See [Scattering](/modules/scattering/).
- `CrashReports`: when a run of the game crashes or is closed by force, the next start writes a report to `user://crashes`, with the versions, the system, context the game adds and the end of the log. See [Crash reports](/modules/crash-reports/).
- Crash reports can go to Purr's online services, with the player's agreement (`privacy/send_crash_reports` in `Options`, off until they agree), or one at a time with `CrashReports.send()`. Email and IP addresses and the player's home folder are removed first. On the service, `npm run crashes` lists them grouped by crash. See [Crash reports](/modules/crash-reports/#sending-them) and [the online services' crash reports](/online/crash-reports/).
- `Options`: the player's settings in one place, saved to `user://options.cfg`. The window mode, vsync, frame rate cap, graphics tier and each audio bus's volume are built in and take effect as they change and as the game starts; add the game's own under `options/` in Project Settings. See [Options](/modules/options/).
- `TimeOfDay`: a sun and moon that cross the sky as the hours pass, warm at dawn and dusk, with the sky and ambient light dimming at night and a signal as each hour begins. See [Time of day](/modules/time-of-day/).
- `TestCase.measure()` times a function once a frame and prints how long a call takes, against the last run on the same computer, so heavy work can be checked before and after a change. See [Testing](/modules/testing/#measuring).
- `InstanceGroup3D`: thousands of copies of a mesh that move (a crowd, units, bullets), given as one array of transforms a frame and drawn in chunks of the world, so what's out of view costs nothing. See [World](/modules/world/#many-moving-copies).

## Changes to check

- The release's download with the Mac, iOS, Apple TV and Vision Pro export templates is now called `purr-<version>-apple-templates.zip` (it was `macos-templates`). The editor's own download and the `.tpz` file are unchanged.
- Godot's own menu controls (`ui_up`, `ui_accept` and the rest) now only answer controllers: a steering wheel's pedals and steering no longer move the highlight round menus. Bind a wheel's buttons to your own menu actions if players should use them there.
- The player's graphics tier (`display/graphics_tier`, starting as `RecommendedGraphics.get_tier()` recommends) is now applied as the game starts: upscaling, anti-aliasing, texture filtering, model detail and the sun's shadow size replace those in Project Settings. If your game applies tiers itself, turn off `rendering/graphics_tier/apply`. See [Graphics settings](/modules/graphics/).
- Purr now has a `TimeOfDay` class. A script with `class_name TimeOfDay` no longer compiles: rename it, or move to Purr's. See [Time of day](/modules/time-of-day/).
- Online services: run `npm run update` before deploying this release. It adds the crash reports' tables and their rate limit.
